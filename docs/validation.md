## Границы проверки

Внешние клиентские прокси, реальные Telegram-токены и клиентские серверы не использовались. Локальная готовность не доказывает доступность внешнего прокси или доставку сообщения. Поддерживаются HTTP/HTTPS parent и SOCKS5 через локальные переходники. По одному независимому экземпляру на клиента, настройки сети и прокси клиент заполняет перед запуском.

## Обновление SOCKS5

- `make test ENGINE=podman`: 25 тестов прошли на Alpine 3.23.
- `make integration ENGINE=podman`: 22 теста прошли на реальном Squid с read-only rootfs и ограниченными capabilities.
- Полный `make deploy`, `make health`, `make status` прошел для списка из трех фиктивных SOCKS5-прокси в отдельной временной копии с внутренней Docker-сетью; ресурсы удалены после проверки.
- Проверены RFC 1928/1929 auth и remote DNS, IPv4/IPv6/domain reply framing, поврежденные и оборванные ответы, бинарный поток 2 MiB с half-close, сохранение открытого туннеля при смене пула, смешанный HTTP/SOCKS5 список, ошибки auth/connect без прямого Telegram, SOCKS5-откат и закрытие слушателей после отклоненного кандидата.
- Независимый reviewer воспроизвел ложный CONNECT 200 при исчерпании 256 слотов. Исправлено явным ограниченным по времени ответом 502; реальный Squid тест подтвердил ошибку при насыщении и успешный туннель после освобождения слотов.
- Реальные данные из клиентского proxy.txt не копировались в код, примеры, тесты или архивы. Использованы только фиктивные loopback SOCKS5-серверы.
